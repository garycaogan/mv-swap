# mv-swap：一键 AI 换人翻拍

给一条高清原片（MV、舞蹈、影视片段）和几张角色图，说清楚「原片里的谁换成哪张图里的人」，它自己切镜头、认人、在 RunningHub 上用 MiniMax H3 换人生成、审片、重跑、超分、拼片，出成片、对照片和一份成本报告。

做法来自我们在 RunningHub 上做的几条换人片：15 秒的闺蜜手势舞、97 秒的《APT.》MV、18 秒的饭撒摇接力。踩过的坑都写进了代码，下面「它怎么做」一节一条条讲。

```bash
python mvswap.py run jobs/apt --source mv.mp4 --start 0 --end 97 \
  --cast "金发女生=cast/girl.jpg" --cast "戴黑帽墨镜的男生=cast/boy.jpg"
```

## 效果

左边是原片（原作者的脸打了码），右边是换人后的成片。一条 9 秒的 1080p 单人舞蹈，用这个仓库的代码一次过审，生成 ¥0.29、超分 ¥0.18，21 分钟出片。动图没有声音，下面可以下载有声原视频。

## 准备

1. **Python 3.10+、ffmpeg 5.1 以上**（`brew install ffmpeg` / `apt install ffmpeg`；Ubuntu 22.04 自带的 4.4 太老），然后 `pip install -r requirements.txt`。想直接贴视频链接的话再装 `yt-dlp`。
2. **两个 key**，复制 `.env.example` 成 `.env` 填上：
   - `RUNNINGHUB_API_KEY`：[RunningHub](https://www.runninghub.cn) 控制台「API 调用」里拿。会员 key 一次跑 5 个任务、扣 RH 币；企业 key 扣钱包、能同时跑很多个，`RUNNINGHUB_CONCURRENCY` 开大。几个 key 用逗号隔开会一起用。
   - `APIMART_API_KEY`：[APIMart](https://apimart.ai)，认人和审片用它的 Gemini 3.8 Flash，平面图形镜头重画用 GPT Image 2.5。想换别家视觉模型，配 `VISION_BASE_URL` / `VISION_API_KEY` / `VISION_MODEL`（OpenAI 兼容接口都行）。
3. **一条高清原片**：720p 以上，最好 1080p 的本地文件。链接也行（走 yt-dlp），但很多网站游客只给低清，低于 720p 工具会停下；确认就用低清时加 `--allow-lowres`，成片会糊。

   ![360p 和 1080p 原片换出来的对比](docs/media/360p-vs-1080p.jpg)

   同样放大看：左边是 360p 原片换出来的，头发和皮肤糊成一片；右边是 1080p 原片换出来的。

4. **角色图**：每个新角色一张，穿着成片里要穿的那套衣服、背景干净，最好是全身。图里摆什么姿势都行：工具默认不把它直接交给 H3，而是拿它把原片每一镜的首帧改成这个人（见下面的 `--ref-mode`）。真人原片配真人照片；动画原片要先按原片画风重画角色，画风才接得上。

用 Claude Code 或 Codex 的话，把这个仓库放进 skills 目录（比如 `~/.claude/skills/mv-swap`），直接说「把这条 MV 里的金发女生换成这张图里的人」，它会照 `SKILL.md` 来跑。

## 用法

```bash
python mvswap.py run jobs/<任务名> --source <文件或链接> --cast "原片里的人=角色图" [--cast …] [--start 秒 --end 秒]
python mvswap.py run jobs/<任务名>        # 断了就原样再跑：参数记在任务目录的 state.json 里，跑过的不重跑，付过费的视觉模型结果不再调，提交过的生成和超分任务接着查
python mvswap.py status jobs/<任务名>     # 到哪一步、每个镜头的情况、花了多少
python mvswap.py assemble jobs/<任务名>   # 只重新拼片和出报告
```

`--cast` 左边是原片里的人，用中文描述到能认出来就行，写**整条片里都不变**的特征（发色、演出服），别写会变的（发型长短、扎没扎起来）：这句会变成每个镜头里找人的依据。我们有一次写了「黑色短发」，到了这个人扎起头发的后台镜头，模型就去换了旁边一个短发戴眼镜的工作人员。同性别替换最稳，男换女、女换男时报告里会提醒。

其他开关：`--crop auto|none|w:h:x:y`（默认自动裁掉上下黑边）、`--no-upscale`（不做超分）、`--max-attempts 3`、`--allow-many-graphic`、`--accept-failed`（看过对照片后接受没过审的镜头，继续付费超分）。

**参考图**（`--ref-mode`，默认 `keyframe`）。H3 会照搬参考图里的姿势：我们测过一条半身舞蹈，第 5–7 秒成片突然变成角色图那样的全身站姿，扶着头发、露出原片里根本没有的短裙；把角色图裁成半身、把镜头切短都没用。所以默认每个换人镜头先做一张这一镜专用的参考图：原片这一镜的首帧和角色图一起交给 GPT Image，姿势、取景、机位、背景和光线取首帧的，脸、发型、发饰、瞳色和看得见的衣服取角色图的。画完让视觉模型验一遍（是不是同一个人、姿势和取景对不对得上、是不是两只手），不过就带着问题重画一次，两次都不过就停下。换成这种参考图之后，同一段舞蹈每一秒都跟原片同景别、同姿势。另外两种：`neutral` 只拿角色图重画一张双手自然下垂、景别和原片一样的中性图，不把原片里的人交给生图模型；`crop` 不生图，只把角色图按原片景别裁成半身、七分身。参考图模式记在任务里，只对新任务生效。

加 `--refs-only` 只准备参考图并验图，先去任务目录的 `refs/` 看脸、发饰、手和留白，满意了去掉这个开关原样再跑，才开始调 H3。生图的任务号、费用和验图结果一出来就记进 `state.json`，断了续跑接着收、不会重复付费；生图接口拒绝（比如不让改真人照片）就把原文写进报告停下，不会改写提示词去绕。

长镜头换了参考图还会漂的话，新建任务加 `--max-segment-seconds 3`：真切镜照旧保留，超过 3 秒的镜头在动作停顿附近切段分别生成再接回，默认 `0` 不切。这个工作流没有首帧约束的输入，段和段之间的接缝要看对照片。

跑完看任务目录里的 `report.md`、`final/compare.mp4`（竖屏左原片右成片，横屏和方形上原片下成片）、`final/sheet.jpg`（成片每秒一帧）和 `final/compare-seconds.jpg`（每个整数秒和末帧的原片、成片并排）。报告里还列出每个镜头用的参考图、生图的输入和费用，以及逐秒审片的结果。只要有镜头所有版本都没过审，工具就跳过付费超分，先在本地免费拼诊断片和对照片，报告里逐个列出镜头和原因；没有可用版本的镜头在诊断片里暂用原片。审片模型偏严，多数能用：看过对照片觉得行，运行 `python mvswap.py run jobs/<任务名> --accept-failed` 接着超分，不会为这次确认多生成版本，确认会记在任务里，之后断了续跑也算数。真不能用的手工修，改完 `state.json` 再跑一次 `run` 会重拼；改过的镜头审片记录还是没过的，加 `--accept-failed` 才会补超分。加了 `--no-upscale` 的任务没有付费超分，不会停下来等确认。

## 它怎么做

1. **取片**：本地文件直接用，链接走 yt-dlp。截取时间段、裁掉黑边、统一成 24fps。
2. **切镜头**：场景分数大于 0.28 先切，再用 0.12 把同色背景里漏掉的切口找出来；前后画面构图还连得上的不算切口，否则舞台闪光、频闪会把一个镜头切成好几段（一条 92 秒的片子第一次切出 104 段，加了这道后 54 段）。超过 14 秒的镜头平均切开。**一个镜头一个任务**：一段里带切镜，模型会打乱镜头顺序、自己编画面。
3. **认人**：视觉模型先把你的中文描述写成原片里每个人的英文外貌，再从角色图写出替换后的样子，顺便判断原片是真人还是动画；然后每个镜头看首、中、尾三帧，标成「换人 / 用原片（没人、字卡、只有嘴或眼睛的特写、剪影）/ 图形（贴纸、手绘这类平面画面）」，记下谁在画面里、景别、有没有字、布景和光线。
4. **生成**：每个镜头补定格尾巴凑成 17k+5 帧（这个工作流只出这种长度，抽风的结尾正好落在被剪掉的部分），放大到约 0.8MP 的同比例尺寸（16:9 是 1184×672）。单人镜头只给那个人这一镜的参考图，不然另一个人会走进画面。提示词只说谁换成谁、景别逐帧跟原片、这个镜头的布景照原片、只取图里的人不取图的底色，图里的人只提供长相和衣服，姿势、手脚位置和人物大小每一刻都跟视频。列道具会让它加贴纸、拉全景；提「每个切镜」它会自己加切镜；只笼统说「布景照原片」，暗场镜头常被定妆照的灰底顶掉，所以每个镜头单独写出它的布景。

   ![抽风的结尾](docs/media/bad-tail.jpg)

   一条 15 秒的舞蹈整段生成，最后不到一秒突然变成了角色的定妆照。补的那截定格尾巴，就是为了把这种结尾剪掉。

5. **审片**：一道颜色检查（画面外圈和原片差太多 = 背景跑了），一道视觉模型逐秒对照原片同一帧（每个整数秒加镜头首尾两帧，左原片右成片）：任一秒景别宽了或窄了一档、机位或姿势对不上、漂回参考图的姿势、露出原片没拍到的下半身，这一版直接不过，总分多高都不算，原因写明第几秒；有一秒缺了或景别判断不出也不过。另外照旧查换对了没有、原来的人还在不在、多没多人、加没加字和贴纸、有没有崩。全都干净才算过。对照帧存在 `review/` 里；每张对照帧带编号，模型把 8.958 秒写成 9 秒也不会漏查。
6. **重跑**：没过的换种子再来；最好的一次只换掉了一部分人时，下一次拿这次的结果当原片，只给没换掉的人再过一遍。最多 3 次，挑分最高的。
7. **图形镜头**：视频模型做不了平面图形，就用 GPT Image 把中间那帧按原来的风格重画成新角色，再慢慢推近撑满时长。
8. **超分**：全部换人镜头都有过审版本（或者你加了 `--accept-failed`）之后，在 RunningHub 上过一遍 SeedVR2，短边放大到成片尺寸，再按原镜头的颜色校一次（放大后整体偏品红）。任务号一提交就记进 `state.json`，断了原样再跑先收原任务。
9. **拼片**：每个镜头按原片的帧数取用，放大到长边 1920，原声配回去，出成片、对照片、缩略图、逐秒对照图和报告。

## 成本和时间（实测）

| 片子 | 镜头 | RunningHub | 生图 / 视觉 | 墙钟 |
|---|---|---|---|---|
| 22 秒 MV 片段（换人 9、原片 2、图形 3） | 14 | ¥1.06 | ¥1.48 / ¥0.1 | 24 分钟 |
| 9 秒 1080p 单人舞蹈（用这个仓库的代码，含超分） | 1 | ¥0.29 + 超分 ¥0.18 | — / ¥0.06 | 21 分钟 |

一条 92 秒、54 个镜头的三维动画 MV，按现在的代码重跑约 ¥23（生成 ¥14、超分 ¥4.2、视觉 ¥4.9）、50 分钟左右。换人镜头每秒约 ¥0.05（会员币）到 ¥0.1（企业钱包），Seedance 2.0 mini 480p 是每秒 ¥0.1 左右。一条 1 分半的 MV 大约 45 个换人镜头，钱包够让它们一起跑的话，半小时左右、¥10 上下。企业钱包按每个在跑的任务预扣一点余额，余额不够时新任务会被拒，工具会等空位再交。

默认的首帧改人参考图，每个换人镜头里的每个人要多生一张 GPT Image（APIMart 2K 约 ¥0.3），验图另算几分钱，没过重画再加一张。一段 9 秒 1080p 单人舞蹈用这种参考图跑完全程约 ¥2.6；镜头多、人多的长 MV 这笔会明显变大，在意成本可以用 `--ref-mode crop`（不生图，但姿势漂回参考图的毛病就回来了）。

动画原片能跑通，但我们自己看下来效果不如真人 MV 和舞蹈，优先选真人原片。

## 文件

- `mvswap.py` 命令入口；`mvswap/pipeline.py` 各阶段和状态；`rh.py` RunningHub（取节点图、排队、预扣满了等空位、断线重试、续跑接着查）；`ai.py` 视觉模型和生图；`media.py` 取片、切镜头、补帧；`vision.py` 认人、打标签、审片；`prompts.py` 提示词；`cast.py` 角色；`references.py` 每镜参考图（首帧改人、中性图）的生图和验图；`framing.py` 景别、裁图和逐秒对照帧；`finish.py` 图形镜头、拼片、报告。
- 用到 RunningHub 上两个公开工作流，节点图运行时用你的 key 现取（`getJsonApiFormat`），缓存在 `~/.cache/mv-swap/`，不随仓库分发：
  - Nick 的 [「MinimaxH3 swap 角色迁移」](https://www.runninghub.cn/post/2109190174289780738)（H3 换人，fl2va/ref2va 混合模型 + 换人 LoRA）
  - C-KIRIN 的 [「视频高清放大+补帧：SeedVR2」](https://www.runninghub.cn/post/1989896719183867905)
  
  作者改了工作流、节点号对不上时，工具会停下并提示。
